# flareosaur

Deno's standard library, ported to Cloudflare Workers with no `nodejs_compat`,
and the Deno examples as plain Workers. Published to JSR as
`@mikepage/flareosaur` (one package, a subpath per std package).

The thesis: the platform is the standard library. Web APIs (`URLPattern`,
`fetch`, `AbortSignal.timeout`, `HTMLRewriter`, `cloudflare:sockets`,
`crypto.subtle`, `Intl`, Web Streams) and the bindings (KV, R2, D1, Queues,
Cron, rate limiting, Durable Objects) come first. std fills the gaps.

An Effect v4 rebuild is kept on the `effect-v4` branch for reference. Don't
bring Effect (or any other runtime dependency) back.

## Layout

- `<pkg>/`: std's code, vendored by `npm run port` from a denoland/std checkout,
  with std's own tests (`*_test.ts`) and `testdata/`. The edits for workerd live
  in `patches/edge.patch`. Never edit a package without regenerating the patch
  (`npm run patch`).
- `deno.json` exports are generated by the port from each package's own
  `deno.json`.
- `examples/<slug>.ts`: one Worker per example. `examples/README.md` is
  generated by `npm run examples`.
- `scripts/`: plain Node scripts (`port`, `make_patch`, `check`, `test`,
  `examples`). No CLI framework: npm scripts with positional arguments are
  enough. If a real CLI is ever needed, use UnJS citty and consola.
- `types/`: ambient types for `deno check` (`web.d.ts`, `wasm.d.ts`).

## Rules for package code (enforced by `npm run check` and `npm test`)

1. Workers only: no `Deno.*`, no `node:` imports, nothing that needs
   `nodejs_compat`. `deno check` runs without the Deno namespace.
2. No runtime dependencies. Imports between packages are relative paths.
3. No I/O, randomness or timers in global scope (workerd forbids them).
   `npm test` imports every export to catch this.
4. Keep std's API. Changes are fixes for workerd, kept small, with a comment
   saying why.
5. std's tests must keep passing in workerd. A test that needs a filesystem,
   subprocesses or Node goes in `scripts/skip.json` with a reason.

## Rules for examples (enforced by `npm run check` and `npm run examples`)

Load the `workers-best-practices` skill (`.claude/skills/`) before changing an
example.

- One file, a Worker module:
  `export default { fetch(request, env, ctx) {...} } satisfies ExportedHandler<Env>`.
  Script-style examples use `script` from `examples/_lib/script.ts`.
- Web APIs and bindings first; `@mikepage/flareosaur/<pkg>` where std clearly
  helps. No other imports.
- Nothing outlives the request that started it: work after the response goes
  through `ctx.waitUntil`. No per-isolate mutable state that matters for
  correctness: use KV, a Durable Object or the rate limiting binding.
- The JSDoc header is the test: `@title`, `@difficulty`, `@tags`, `@group`,
  `@resource`, `@bindings`, `@check`. The syntax is documented at the top of
  `scripts/examples.mjs`.
- A commented walkthrough in the style of docs.deno.com/examples. Short
  sentences. `deno fmt` style.

## Commands

- `npm run check`: `deno check` every package module, then `tsc` the examples
  against `@cloudflare/workers-types` through emitted declarations.
- `npm test [-- <pkg>[/<file>_test.ts]]`: std's tests inside workerd
  (Miniflare).
- `npm run examples [-- <slug>...]`: run the examples' checks in workerd.
- `npm run port -- ../std`, `npm run patch -- ../std`: vendor std, regenerate
  the patch.
- `npx jsr publish --dry-run`: what CI runs before publishing.

Releases: CalVer `YYYYMMDD.0.N` in `deno.json`, see the README. Bump only when
the published package changes.

Commit messages: Conventional Commits, ending with the Co-Authored-By line.
